# Find, fix, and replay UX issues

1. Locate `remorsearch-ux-qa` through host skill discovery or `REMORSEARCH_SKILL_DIR` pointing to the installed folder with `SKILL.md`. Record its revision when available. If missing, offer the [upstream install steps](https://github.com/remorser58/remorsearch_ux_qa_skill#install) and install only with the user's authorization. Continue useful [local visual and interaction QA](../references/visual-qa.md) if the skill or driver is unavailable, labeling the run **fallback**, its coverage and its gaps.
2. Follow Remorsearch's `persona-qa` workflow for the baseline. Supply route/build ID, 3–5 concrete tasks, fixtures, approvals and design intent. Use the approved `DESIGN.md` and `/system` as this workflow's design evidence; record Figma as out of comparison scope if none exists. Honor any setup or design requirements the installed skill imposes, and keep its QA pass read-only. Use the desktop, tablet and phone device profiles (e.g. `laptop-1440`, `galaxy-tab-s9`, `iphone-15` where available), relevant pointer/touch paths and a desktop keyboard-only path. Probe state preservation and recovery for tasks that mutate safe test data.
3. When the host allows, have a separate reader do a screenshot-only pass; reproduce the same task in a screenshot + accessibility audit using saved scenarios (`node drivers/web/ergo_drive.mjs run …` from the skill root, with its installed CLI options). Mark a self-pass as such. Run the skill's measurement and evidence tools, e.g. `scripts/ergo_qa.py swarm` at P2, and validate its evidence bundle. Check reflow warnings in the actual viewport; get a second pass on P0/P1. Use the Remorsearch report structure and the [Ultradesign round index](../assets/templates/qa-evidence.md). Capture 390/768/1440 widths or the agreed device widths.
4. In implementation, give the builder a fix packet of confirmed open findings: ID, reproduction, expected state, owning layer (screen JSON, catalog component or frame, `DESIGN.md`) and decisions to preserve. Implement scoped fixes in that layer; a change to the catalog, the system or an approved table goes back to its gate. Rerun `a2ui-validate`, the guard and `hierarchy-check` after each fix. Replay the same scenarios, devices and data against the new build; repeat prior passing tasks for regressions. Save reports/run IDs for baseline 0, then fix/replays 1–3 with resolved/open/new/regression IDs. Stop when agreed issues are resolved, the same finding stays open two rounds, a regression persists through the next round, or three fix rounds have run. Report any remaining issue and risk to the user. Read-only review reports the baseline and proposed corrections.
5. In OMP persist each round with `ultradesign_checkpoint(action="qa_round", qaRound={round,method,report,openFindings})`; on other hosts keep the equivalent entries in the round index. Complete QA with the current build's report, remaining scope and reproducible evidence, not an aggregate score.

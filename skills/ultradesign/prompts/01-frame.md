# Frame the real screen

1. Read the brief, inspect the existing route and system, and confirm what kind of work the user requested. For a new product use the real task and material the user has, including their actual copy, representative data, and authorized brand assets.
2. Record in a private `brief.md`: product and route; who is using it and why; one primary outcome and 3–5 relevant actions or content checks; real copy/data/assets and source; adjacent states; target devices, existing stack, system, and scope. For an owner-authorized product, record the exact target URL for the board's separate current-screen capture. Use only representative data appropriate for local artifacts.
3. State the design questions the board should help answer (e.g. “How does a developer landing hero make an agent workflow legible?”). Ask for a missing material fact only when inspection cannot establish it. Carry the brief into the board.

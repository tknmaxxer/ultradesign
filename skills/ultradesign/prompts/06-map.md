# Agree the hierarchy before generating

1. For each screen, or each section of a landing page, write `hierarchy.json` following the [hierarchy guide](../references/hierarchy.md): one P1, the P2 and P3 items, one primary action, the layout frame, and word budgets. Use the brief's task and real content. Say why the P1 and the primary action are the right ones for the task.
2. For a multi-section page, number the sections, attach the reference crop whose layout each section takes, the visual (which catalog component or product content fills it), and one motion line. Keep each heading short and each description to one sentence; the page earns length through content and visuals, not paragraphs.
3. Render the board with `scripts/screen-map` and show it. The owner approves, reorders, drops sections or changes priorities by number. Record the approved tables; generation uses them exactly.

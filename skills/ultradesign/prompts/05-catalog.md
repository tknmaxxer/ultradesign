# Expose the system as an A2UI catalog

1. Start from the approved `DESIGN.md`, `/system` and the picked references. Follow the [catalog and renderer guide](../references/a2ui.md). List the components the screen needs and give each a role: frame, content or action. Content takes `emphasis` p1/p2/p3, actions take primary/secondary, and the renderer maps those to the system's type and button roles. Links, media and events are enums of approved targets.
2. Build each layout frame from something the owner has already approved or picked: recreate that arrangement with the system's components and the project's real content. Use a direct [showcase link](../references/catalog.md#component-showcases) when a component needs an example. Render the frame beside its source at matching widths and keep the proportions, alignment and rhythm that made the source work. Every component should draw real content; a box with an icon and two words is missing its content.
3. Implement the catalog with the stack's official A2UI renderer path (React: `@a2ui/react` custom catalog, Base UI and CSS Modules). Mark the generated area and component roots for the hierarchy check, add the `/system` catalog view with every component at every emphasis, and install the [guard](../assets/templates/guard/README.md) as the build's first step. Run `scripts/a2ui-validate --catalog`, the guard and the build until all pass.
4. Show the owner the catalog `/system` render at 390 and 1440, each frame beside its source, the component list with roles, and what the guard enforces. Wait for approval of the catalog. Catalog changes later in the run come back to this gate.

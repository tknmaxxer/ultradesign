# Build in two shots

1. **Reconstruct.** With the approved system, open the chosen images and their source states. In a private work surface rebuild the composition with our components: region weights, alignment, proportions, rhythm, states and visual focus. When a component needs an example, use an exact [showcase link](../references/catalog.md#component-showcases), e.g. a 21st.dev pattern for a hero or a UIArc control with the relevant state. Implement the behavior on your existing or headless primitives, and use assets you have rights to use. Capture the reconstruction in the matching viewport/state and compare it with the reference before adapting it.
2. **Adapt and subtract.** Replace the specimen with the real product data and assets and bind real behavior. Keep the structure that helped the task. Group content by spacing, tone, weight and useful separators. Prefer component variants for meaningful differences; reserve elevation for overlays that need it. Walk every affected region against its purpose and keep the controls, context and cues needed to use it.
3. Verify the implementation runs at its real route. Save both shots plus a note about which structure carried over and how it changed. Use 390, 768 and 1440 CSS px for the adapted captures unless the real device set calls for another width. Send the route, user tasks, approved system and observed build ID to QA.
